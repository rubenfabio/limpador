# T-00.03 — E2E da interface com núcleo simulado

**Feature:** F00 · **Fase:** MVP · **Depende de:** T-00.01

## Regras de negócio

- A interface roda isolada, com as chamadas ao núcleo substituídas por respostas configuradas no teste (resultado de análise, erros, progresso, pedidos de confirmação).
- Os testes interagem como um usuário: clicam, digitam, filtram, selecionam e conferem o que aparece.
- O teste consegue verificar **quais chamadas** a interface fez ao núcleo (ex.: "a confirmação 🔴 só chamou limpar depois da caixa marcada").
- Há um conjunto de respostas pré-montadas reutilizáveis. As de análise (vazia, típica, 10 mil itens, coletor com erro, Docker parado) são criadas pelas tarefas de F08 que introduzem essas telas.
- Falhas produzem captura de tela e registro.

## Critérios de aceite

- [x] **CA1** Dado o núcleo simulado respondendo a um comando, quando a interface abre, então exibe o dado vindo do núcleo.
- [x] **CA2** Dada a interface aberta, quando o teste consulta as chamadas, então vê exatamente os comandos que a interface enviou ao núcleo.
- [x] **CA3** Dado um teste que falha, quando termina, então há uma captura de tela da falha.
- [x] **CA4** Dado o comando de e2e de interface, quando roda localmente, então não precisa do app compilado nem do núcleo.

## Histórico

Em 2026-10-17, por decisão do dono do produto, os critérios que dependiam de telas ainda inexistentes foram movidos para as tarefas dessas telas:
- "análise típica → painel com totais corretos" virou o CA6 de T-08.01;
- "Limpar sem marcar a caixa 🔴 não chama limpeza" virou o CA5 de T-09.01.
