# T-00.06 — Verificações locais e CI

**Feature:** F00 · **Fase:** MVP · **Depende de:** T-00.03, T-00.04, T-00.05

## Pré-condição

O projeto precisa estar num repositório git hospedado no GitHub. Criar o repositório é decisão do usuário.

## Regras de negócio

| Quando | O que roda | Bloqueia? |
|---|---|---|
| Antes do commit (local) | Formatação, lint, unitários dos módulos alterados (alvo: menos de 1 minuto) | Sim, o commit |
| Cada push (CI, Windows) | Formatação, lint, unitários, integração, e2e de interface, e2e do app real, rastreabilidade | Sim, o merge |
| Cada PR (CI) | Tudo acima + mutação incremental com metas | Sim, o merge |
| Semanal (CI) | Mutação completa + relatório de tendência | Não bloqueia; abre aviso se uma meta cair |

- O CI roda em **Windows**, que é a plataforma alvo.
- Os artefatos de falha (capturas de tela, registros, relatórios de mutação) ficam disponíveis no CI.
- Os mesmos comandos do CI existem localmente, para reproduzir uma falha sem adivinhação.

## Critérios de aceite

- [x] **CA1** Dado um commit com um teste unitário quebrado, quando o desenvolvedor tenta commitar, então o commit é recusado.
- [ ] **CA2** Dado um push com o e2e falhando, quando o CI roda, então o resultado é falha e a captura de tela fica disponível.
- [ ] **CA3** Dado um PR que derruba um módulo crítico para 80% de mutação, quando o CI roda, então o merge fica bloqueado.
- [ ] **CA4** Dada a execução semanal com uma meta caindo, quando termina, então um aviso é aberto.
- [x] **CA5** Dado qualquer passo do CI, então existe um comando local equivalente documentado.
