# T-00.06 — Verificações locais e CI

**Feature:** F00 · **Fase:** MVP · **Depende de:** T-00.03, T-00.04, T-00.05

## Regras de negócio

O CI roda localmente ([ADR-0017](../../docs/adr/0017-ci-local.md)):

| Quando | O que roda | Bloqueia? |
|---|---|---|
| Antes do commit | Formatação, lint, unitários dos módulos alterados (alvo: menos de 1 minuto) | Sim, o commit |
| Antes do push | Formatação, lint, unitários, integração, e2e de interface, e2e do app real, rastreabilidade + mutação incremental com metas | Sim, o push |
| Semanal (tarefa agendada do Windows) | Mutação completa | Não bloqueia; mostra uma notificação se uma meta cair |

- Push que só muda documentação não roda o CI local.
- Os artefatos de falha (capturas de tela, registros, relatórios de mutação) ficam em `reports/`.
- O workflow do GitHub existe, mas só roda quando disparado manualmente; cada passo dele tem equivalente local documentado.
- A `main` no GitHub é protegida contra force-push e exclusão.

## Critérios de aceite

- [x] **CA1** Dado um commit com um teste unitário quebrado, quando o desenvolvedor tenta commitar, então o commit é recusado.
- [x] **CA2** Dado um push com o e2e falhando, quando o CI local roda, então o push é recusado e a captura de tela fica disponível em `reports/`.
- [x] **CA3** Dada uma alteração que derruba um módulo crítico abaixo da meta de mutação, quando o CI local roda antes do push, então o push é recusado.
- [x] **CA4** Dada a execução semanal com uma meta caindo, quando termina, então um aviso (notificação do Windows) é mostrado.
- [x] **CA5** Dado qualquer passo do CI, então existe um comando local equivalente documentado.

## Histórico

Em 2026-10-17 o CI no GitHub Actions foi substituído pelo CI local (ADR-0017): a conta do GitHub estava impedida de rodar Actions, e o dono do produto decidiu não depender dele. CA2 a CA4 foram reescritos para o equivalente local.
