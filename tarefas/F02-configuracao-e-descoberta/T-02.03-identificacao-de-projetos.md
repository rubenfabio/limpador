# T-02.03 — Identificação de projetos

**Feature:** F02 · **Fase:** MVP · **Depende de:** T-02.02

## Regras de negócio

**Marcadores de projeto:** `.git`, `package.json`, `pyproject.toml`, `requirements.txt`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle(.kts)`, `*.sln`, `*.csproj`, `composer.json`, `Gemfile`, `docker-compose.yml`, `compose.yaml`. A lista é configurável.

**Raiz do projeto**
- Se a pasta está dentro de um repositório git, o projeto é a **raiz do repositório**. Monorepos (vários `package.json` num repositório) são **um** projeto.
- Sem git: a pasta mais externa com marcador.
- Repositórios aninhados (clones dentro de clones, submódulos) são projetos separados.
- Worktrees são reconhecidas como worktrees do repositório de origem, não como projetos novos.

**Varredura**
- Nunca entra em pastas de dependência ou build (`node_modules`, `.venv`, `target`, `vendor`, `.git`...).
- Profundidade máxima configurável (padrão: 6 níveis a partir da raiz).
- Nome do projeto = nome da pasta; o caminho completo aparece no detalhe.

## Critérios de aceite

- [x] **CA1** Dado um repositório git com `apps/web/package.json` e `apps/api/package.json`, quando identificado, então é um único projeto.
- [x] **CA2** Dada uma pasta sem git com `package.json`, quando identificada, então é um projeto.
- [x] **CA3** Dado um repositório clonado dentro de outro, quando identificado, então são dois projetos.
- [x] **CA4** Dada uma worktree do repositório A, quando identificada, então aparece como worktree de A, não como projeto novo.
- [x] **CA5** Dado um `package.json` dentro de `node_modules`, quando a varredura roda, então não é considerado projeto.
- [x] **CA6** Dado um projeto a 8 níveis de profundidade com limite 6, quando a varredura roda, então ele não é encontrado.
