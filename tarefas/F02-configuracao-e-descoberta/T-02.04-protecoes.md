# T-02.04 — Proteções

**Feature:** F02 · **Fase:** MVP · **Depende de:** T-02.03

## Contexto

O usuário precisa ter certeza de que certas coisas **nunca** serão tocadas.

## Regras de negócio

| Proteção | Efeito |
|---|---|
| **Projeto fixado** | O projeto é sempre ativo (nunca "parado"). Seus itens continuam visíveis, com peso de projeto ativo |
| **Caminho protegido** | Nada dentro do caminho é limpável. Os itens saem do ranking e vão para "Protegidos" |
| **Branches protegidas** | Padrões que nunca são candidatos. Padrão inicial: `main`, `master`, `develop`, `dev`, `release/*`, `hotfix/*`. Editável |
| **Recursos Docker protegidos** | Padrões de nome de imagem e volume que nunca são candidatos (ex.: `postgres-dados-pessoais`) |

- Proteção vence qualquer outra regra (I10).
- Proteções podem ser criadas direto a partir de um item ("proteger isto").
- A visão "Protegidos" mostra cada item protegido e qual regra o protege.

## Critérios de aceite

- [ ] **CA1** Dado o caminho protegido `C:\Projetos\tcc`, quando a análise roda, então nenhum item de lá aparece no ranking e todos aparecem em "Protegidos".
- [ ] **CA2** Dada uma branch `release/2.0` mergeada, quando a análise roda, então ela não é candidata.
- [ ] **CA3** Dado um volume que casa com um padrão protegido, quando a análise roda, então ele não é candidato.
- [ ] **CA4** Dado um item no ranking, quando o usuário escolhe "proteger isto", então ele sai do ranking na hora e a proteção fica salva.
- [ ] **CA5** Dado um projeto fixado sem atividade há 200 dias, quando a análise roda, então ele está ativo.
