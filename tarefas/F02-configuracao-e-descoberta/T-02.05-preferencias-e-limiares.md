# T-02.05 — Preferências e limiares

**Feature:** F02 · **Fase:** MVP · **Depende de:** —

## Regras de negócio

Todas as regras que dependem de um número usam estas preferências:

| Preferência | Padrão | Faixa permitida |
|---|---|---|
| Inatividade de projeto | 30 dias | 7–365 |
| Prazo da quarentena | 14 dias | 1–90 |
| Limpeza automática de 🟢 | definida no onboarding | liga/desliga |
| Análise agendada | diária, 13h | diária / semanal / desligada + horário |
| Iniciar com o sistema | definida no onboarding | liga/desliga |
| Alerta de recuperável | 10 GB | 1–500 GB |
| Alerta de disco livre | 15% | 5–50% |
| Idade mínima de temporários | 7 dias | 1–90 |
| Idade de stash antigo | 30 dias | 7–365 |
| Idade de arquivo antigo em Downloads | 30 dias | 7–365 |
| Idade de sessão de agente antiga | 90 dias | 14–730 |
| Camada gravável de container considerada "com dados" | 100 MB | 1 MB–10 GB |
| Consulta ao GitHub | ligada se houver autenticação | liga/desliga |
| Atualizar remotos git antes de analisar | desligada | liga/desliga |
| Adiar análise na bateria | ligada | liga/desliga |
| Retenção do histórico | 365 dias | 30–3650 |
| Tempo limite por coletor | 5 min | 1–60 min |
| Profundidade de varredura | 6 | 2–15 |

- Valores fora da faixa são recusados com mensagem.
- Mudanças valem a partir da próxima análise.
- "Restaurar padrões" volta tudo ao padrão, menos pastas raiz e proteções.
- As preferências sobrevivem a atualizações do app.

## Critérios de aceite

- [x] **CA1** Dada uma instalação nova, quando as preferências são lidas, então todos os padrões da tabela valem.
- [x] **CA2** Dado o valor 0 para a quarentena, quando salvo, então é recusado.
- [x] **CA3** Dada a inatividade alterada para 60 dias, quando a próxima análise roda, então usa 60 dias.
- [x] **CA4** Dado "restaurar padrões", quando executado, então pastas raiz e proteções continuam intactas.
- [x] **CA5** Dado o app reiniciado, quando as preferências são lidas, então os valores salvos estão lá.
