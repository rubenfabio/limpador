# T-03.02 — Imagens Docker

**Feature:** F03 · **Fase:** MVP · **Depende de:** T-03.01, T-01.06

## Regras de negócio

| Situação | Risco | Natureza |
|---|---|---|
| Imagem **sem tag** (dangling) e sem uso | 🟢 | Recriável |
| Imagem com tag, não usada por nenhum container (rodando ou parado) e criada ou baixada há mais tempo que o limiar de inatividade | 🟡 | Recriável (baixar de novo ou rebuild) |
| Usada por container rodando | ⛔ | — |
| Usada só por container parado | Não candidata; o motivo indica "libera ao remover o container X" | — |
| Casa com padrão protegido | Protegida | — |

- **Tamanho liberável = espaço exclusivo da imagem.** Camadas compartilhadas com outras imagens que ficam não contam.
- O motivo traz repositório:tag, idade, tamanho exclusivo e o último container que a usou, se houver.
- **Como recriar:** "baixar de novo com pull" (imagem de registro) ou "rebuild do projeto X" (imagem local associada a projeto).
- Associação a projeto: pelos rótulos do Compose dos containers que a usaram ou pelo prefixo de nome do projeto do Compose.

## Critérios de aceite

- [ ] **CA1** Dada uma imagem sem tag e sem uso, quando analisada, então é 🟢.
- [ ] **CA2** Dada `node:18` sem container e baixada há 90 dias, quando analisada, então é 🟡 com "baixar de novo" em "como recriar".
- [ ] **CA3** Dada uma imagem usada por container rodando, quando analisada, então é ⛔.
- [ ] **CA4** Dadas duas imagens que compartilham uma camada de 500 MB, quando só uma é candidata, então o tamanho liberável dela não inclui os 500 MB.
- [ ] **CA5** Dada uma imagem que não pôde ser removida por dependência, quando a limpeza roda, então o item aparece como "falhou" com o motivo.
