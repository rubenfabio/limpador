# T-03.04 — Volumes órfãos

**Feature:** F03 · **Fase:** MVP · **Depende de:** T-03.01, T-09.04

## Contexto

Volumes guardam dados de bancos e serviços. É o item Docker mais perigoso de apagar.

## Regras de negócio

- **Candidato:** volume não referenciado por nenhum container, rodando ou parado.
- Sempre **🔴, conteúdo do usuário, destino quarentena**.
- O motivo traz: nome, se é anônimo (nome em hash) ou nomeado, tamanho, data de criação, projeto do Compose (rótulo) e o último container conhecido que o usou.
- **Quarentena do volume:** o conteúdo é exportado para um arquivo na quarentena junto com os metadados (nome, rótulos, driver); depois o volume é removido.
- **Restauração:** recria o volume com o mesmo nome, rótulos e conteúdo.
- Se não houver espaço livre suficiente para exportar, a ação é bloqueada com mensagem ("precisa de X GB livres").
- A interface deixa claro que o espaço só volta na purga da quarentena.

## Critérios de aceite

- [ ] **CA1** Dado um volume sem nenhum container, quando analisado, então é 🔴 com destino quarentena.
- [ ] **CA2** Dado um volume usado por container parado, quando analisado, então não é candidato.
- [ ] **CA3** Dado um volume com um arquivo de teste, quando vai para a quarentena e é restaurado, então o arquivo volta idêntico e o volume tem o mesmo nome e rótulos.
- [ ] **CA4** Dado espaço livre menor que o tamanho do volume, quando a limpeza é pedida, então é bloqueada com mensagem.
- [ ] **CA5** Dado um volume com padrão protegido, quando analisado, então não é candidato.
