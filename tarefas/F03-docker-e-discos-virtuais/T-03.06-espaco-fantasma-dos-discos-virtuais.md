# T-03.06 — Espaço fantasma dos discos virtuais

**Feature:** F03 · **Fase:** MVP · **Depende de:** T-03.01

## Contexto

O Docker Desktop e as distros WSL guardam tudo num arquivo de disco virtual que **cresce, mas não encolhe sozinho**. Na máquina do usuário são 17,0 GB (`docker_data.vhdx`) + 16,3 GB (`ext4.vhdx`). Depois de um prune, o espaço continua preso nesse arquivo.

## Regras de negócio

- Encontrar os discos virtuais do Docker Desktop e de cada distro WSL nos locais do catálogo.
- Para cada disco:
  - **tamanho do arquivo** no Windows;
  - **uso interno**: espaço realmente ocupado dentro do disco, quando dá para medir sem iniciar nada (Docker ou distro já rodando);
  - **espaço fantasma** = tamanho do arquivo − uso interno.
- Se não der para medir o uso interno, o item mostra "não medido: inicie o Docker/a distro para medir", com o tamanho do arquivo apenas.
- O item só aparece se o espaço fantasma for de pelo menos 1 GB, ou se não tiver sido medido.
- Risco 🟢, natureza recriável, ação **Compactar**, efeito colateral "interrompe o Docker/WSL".
- Se o disco já estiver em modo de encolhimento automático (esparso), o motivo informa.
- **Previsão**: quando houver itens Docker selecionados para limpeza, o item mostra "após a limpeza, compactar libera cerca de X GB".

## Critérios de aceite

- [ ] **CA1** Dado um disco de 17 GB com 5 GB de uso interno, quando analisado, então o espaço fantasma é 12 GB.
- [ ] **CA2** Dado o Docker parado, quando analisado, então o disco aparece como "não medido" e o Docker continua parado.
- [ ] **CA3** Dado um espaço fantasma de 300 MB, quando analisado, então o item não aparece.
- [ ] **CA4** Dados 6 GB de imagens Docker selecionados, quando o item do disco é exibido, então mostra a previsão de ganho somando os 6 GB.
- [ ] **CA5** Dada uma distro WSL não usada pelo Docker, quando analisada, então aparece como item separado com o nome da distro.
