# T-04.02 — Saídas de build

**Feature:** F04 · **Fase:** MVP · **Depende de:** T-02.03

## Regras de negócio

**Pastas reconhecidas** (lista configurável): `.next`, `.nuxt`, `.svelte-kit`, `.astro`, `.output`, `dist`, `build`, `out`, `.turbo`, `.parcel-cache`, `.vite`, `.angular/cache`, `coverage`, `storybook-static`.

**Regra de segurança**
- Em projeto com git: só é candidata se a pasta estiver **ignorada pelo git**.
- Em projeto sem git: só são candidatas as pastas de nome inequívoco (`.next`, `.nuxt`, `.svelte-kit`, `.astro`, `.turbo`, `.parcel-cache`, `.vite`, `.angular/cache`). `dist`, `build`, `out` e `coverage` **não** são candidatas sem git.

**Item**
- Um item por projeto, agrupando as saídas de build.
- Risco 🟡, recriável, exclusão direta.
- Como recriar: o script `build` do projeto, se existir; senão, "refeito no próximo build ou dev".

## Critérios de aceite

- [x] **CA1** Dado um `dist` versionado no git, quando analisado, então não é candidato.
- [x] **CA2** Dado um `.next` ignorado pelo git, quando analisado, então é candidato 🟡.
- [x] **CA3** Dado um projeto sem git com `build/`, quando analisado, então `build/` não é candidato.
- [x] **CA4** Dado um projeto sem git com `.next`, quando analisado, então `.next` é candidato.
- [x] **CA5** Dado um projeto com script `build`, quando analisado, então "como recriar" mostra o comando.

## Notas de implementação

- `git check-ignore` responde "ignorada" para a pasta mesmo com arquivos versionados dentro; por isso uma pasta com qualquer arquivo rastreado (`git ls-files`) nunca é candidata.
- Se o git falhar, nenhuma pasta do projeto é oferecida.
