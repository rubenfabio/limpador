# T-04.04 — Ecossistema Python

**Feature:** F04 · **Fase:** MVP · **Depende de:** T-02.03, T-01.06

## Regras de negócio

| Item | Como reconhecer | Risco | Natureza |
|---|---|---|---|
| Ambiente virtual do projeto | Pasta com `pyvenv.cfg` dentro do projeto (`.venv`, `venv`, `env`...) | 🟡 se houver manifesto (`requirements*.txt`, `pyproject.toml`, `poetry.lock`, `uv.lock`, `Pipfile.lock`) | Recriável |
| Ambiente virtual **sem manifesto** | Idem, sem nenhum manifesto | 🔴 (não dá para recriar com segurança) | Conteúdo do usuário |
| Caches de projeto | `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox` | 🟢 | Recriável |
| Caches globais | pip, uv, poetry | 🟢 (comando oficial) | Recriável |

- Como recriar o ambiente: o comando correspondente ao manifesto (ex.: `uv sync`, `poetry install`, `pip install -r requirements.txt`).
- Caches de projeto são agrupados num único item por projeto.
- Ambientes conda ficam fora do MVP.

## Critérios de aceite

- [ ] **CA1** Dado um `.venv` com `uv.lock`, quando analisado, então é 🟡 com "como recriar" igual a `uv sync`.
- [ ] **CA2** Dado um `.venv` sem nenhum manifesto, quando analisado, então é 🔴 e vai para a quarentena.
- [ ] **CA3** Dados 40 `__pycache__` num projeto, quando analisados, então formam um único item 🟢.
- [ ] **CA4** Dado o cache global do pip, quando analisado, então é 🟢 e elegível para automação.
