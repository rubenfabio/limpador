# T-04.05 — Outros ecossistemas (Go, Rust, Java, .NET)

**Feature:** F04 · **Fase:** MVP · **Depende de:** T-04.02

## Contexto

Ecossistemas diferentes seguem o mesmo padrão: pasta de build por projeto e cache global. As regras devem ser **orientadas a dados** (uma tabela de catálogo), para que um ecossistema novo entre sem lógica nova.

## Regras de negócio

| Ecossistema | Item | Escopo | Risco | Como recriar |
|---|---|---|---|---|
| Go | cache de build | global | 🟢 | refeito no próximo build |
| Go | cache de módulos | global | 🟡 | baixado no próximo build |
| Rust | `target/` | projeto (com `Cargo.toml`) | 🟡 | `cargo build` |
| Rust | registry do cargo | global | 🟡 | baixado no próximo build |
| Java | `.gradle/` | projeto | 🟢 | refeito pelo Gradle |
| Java | `build/` (ignorado pelo git) | projeto (com Gradle) | 🟡 | `gradle build` |
| Java | `target/` (ignorado pelo git) | projeto (com `pom.xml`) | 🟡 | `mvn package` |
| Java | caches do Gradle e repositório Maven | global | 🟡 | baixado no próximo build |
| .NET | `bin/` e `obj/` (ignorados pelo git) | projeto (com `.csproj`) | 🟡 | `dotnet build` |
| .NET | pacotes NuGet | global | 🟡 | comando oficial de limpeza do NuGet |

- As mesmas regras de git ignore de T-04.02 valem para pastas de build com nome genérico.
- O catálogo indica, por linha: marcador do projeto, caminho, risco, comando de limpeza oficial (se houver) e como recriar.

## Critérios de aceite

- [ ] **CA1** Dado um projeto Rust com `target/` de 4 GB, quando analisado, então é 🟡 com `cargo build`.
- [ ] **CA2** Dado um `bin/` versionado num projeto .NET, quando analisado, então não é candidato.
- [ ] **CA3** Dada uma linha nova no catálogo para um ecossistema fictício, quando a análise roda, então os itens dele aparecem sem mudança de código.
- [ ] **CA4** Dado o cache de build do Go, quando analisado, então é 🟢 e elegível para automação.
