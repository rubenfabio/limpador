# T-05.03 — Detecção de merge via GitHub

**Feature:** F05 · **Fase:** MVP · **Depende de:** T-05.02

## Regras de negócio

**Quando consulta**
- O remoto está no GitHub, a preferência está ligada e existe autenticação **já configurada** na máquina (ex.: login da CLI do GitHub ou credencial do git).
- O app **não pede token** no MVP. Sem autenticação, mostra como habilitar e segue só com os sinais locais, com o rótulo "verificação limitada".
- Só consulta metadados de PR; nenhum código é enviado.

**Como interpreta**

| Situação do PR com head = branch | Veredito | Risco |
|---|---|---|
| Mergeado e a ponta local é igual ao último commit do PR (ou ancestral dele) | Mergeada via PR #N | 🟢 |
| Mergeado, mas a ponta local tem commits depois do PR | Commits após o merge | ⛔ se esses commits não estiverem em nenhum remoto; 🔴 se estiverem |
| Fechado sem merge | PR fechado sem merge | 🔴 |
| Aberto | Não candidata | — |
| Nenhum PR | Vale o veredito local (T-05.02) | — |

- Quando o GitHub e os sinais locais divergem, vale o **mais conservador**.
- Os resultados ficam em cache por (repositório, branch, commit da ponta) e não são consultados de novo enquanto a ponta não mudar.
- Respeitar o limite de requisições da API; se for atingido, o restante fica com "verificação limitada".

## Critérios de aceite

- [ ] **CA1** Dada uma branch com PR mergeado por squash e ponta local igual ao head do PR, quando analisada com GitHub, então é "Mergeada via PR #N" 🟢.
- [ ] **CA2** Dada uma branch com PR mergeado e 1 commit local posterior não enviado, quando analisada, então é ⛔.
- [ ] **CA3** Dada uma branch com PR fechado sem merge, quando analisada, então é 🔴.
- [ ] **CA4** Dada uma máquina sem autenticação, quando analisada, então os repositórios mostram "verificação limitada" e os vereditos locais valem.
- [ ] **CA5** Dada uma segunda análise sem mudança na ponta, quando roda, então nenhuma nova consulta é feita para essa branch.
