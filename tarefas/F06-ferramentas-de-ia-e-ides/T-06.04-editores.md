# T-06.04 — Caches e armazenamento de editores

**Feature:** F06 · **Fase:** MVP · **Depende de:** T-01.04

## Regras de negócio

**VS Code e derivados** (Cursor e outros com a mesma estrutura, via catálogo):

| Item | Regra | Risco |
|---|---|---|
| workspaceStorage órfão | Entrada cujo workspace ou pasta referenciada **não existe mais** (comum com worktrees apagadas). Agrupado num item por editor | 🟢 |
| Instaladores de extensão em cache | Pasta de VSIX em cache | 🟢 |
| Versões antigas de extensão | Mesma extensão em versão mais antiga que a instalada, ou marcada como obsoleta | 🟢 |
| Caches gerais | Cache, CachedData, Code Cache, GPUCache | 🟢 só com o editor **fechado**; aberto → ⛔ |

**JetBrains**
- Pastas de configuração e cache de versões antigas de um produto quando existe versão mais nova do mesmo produto → 🟡.

## Critérios de aceite

- [ ] **CA1** Dadas 30 entradas de workspaceStorage, 12 apontando para pastas inexistentes, quando analisado, então um item agrupa as 12.
- [ ] **CA2** Dado o VS Code aberto, quando os caches gerais são revalidados, então ficam ⛔ "editor aberto".
- [ ] **CA3** Dadas duas versões da mesma extensão, quando analisado, então só a mais antiga é candidata.
- [ ] **CA4** Dado o IntelliJ 2023.3 e o 2024.2 instalados, quando analisado, então as pastas do 2023.3 são 🟡.
