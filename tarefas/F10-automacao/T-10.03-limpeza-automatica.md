# T-10.03 — Limpeza automática de itens seguros

**Feature:** F10 · **Fase:** MVP · **Depende de:** T-10.02, T-09.03

## Regras de negócio

- Roda após a análise agendada, se a preferência estiver ligada.
- **Executa apenas** itens elegíveis (T-01.02): 🟢 + recriável + sem efeitos colaterais + não protegido (I8).
- Além disso, itens ligados a projeto só entram se o projeto estiver **inativo**; itens sem projeto (caches globais) sempre entram.
- **Nunca**: compactação, lixeira, itens com destino quarentena, ações que parem serviços ou fechem programas.
- A revalidação (T-09.02) vale normalmente.
- Toda ação é registrada com a origem "automática".
- Ao final, uma notificação discreta: "Limpeza automática liberou X GB" (pode ser desligada).
- Respeita a pausa de 24 h da bandeja.

## Critérios de aceite

- [ ] **CA1** Dados um cache npm 🟢, um `node_modules` 🟡 e um volume 🔴, quando a limpeza automática roda, então só o cache é limpo.
- [ ] **CA2** Dado um `__pycache__` 🟢 de projeto ativo, quando a limpeza automática roda, então ele não é limpo.
- [ ] **CA3** Dado espaço fantasma 🟢 no disco do Docker, quando a limpeza automática roda, então não há compactação.
- [ ] **CA4** Dada uma limpeza automática concluída, então as entradas do log têm a origem "automática" e a notificação mostra o total liberado.
- [ ] **CA5** Dada a automação pausada, quando a análise agendada roda, então nenhuma limpeza é feita.
